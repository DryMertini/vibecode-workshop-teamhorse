# Feedback is a development step

Ask another person to complete the core task without coaching. “Do you like it?” is not a usability test.

Record under the current step evidence:

1. The task: what you asked the person to do.
2. Observation: what they actually did and where they got stuck.
3. Interpretation: what you think caused the problem; distinguish this from their proposed solution.
4. Decision: one bounded correction, or a reason to defer it.
5. Acceptance: an observable result that would show improvement.
6. Retest: repeat the same task and record what changed.

Example: a visitor submits twice because nothing changes after the first click. “Add animation” is a suggested solution. “A visitor can see whether the request succeeded, and a repeated click does not create a duplicate” is an acceptance criterion.

Put a new feature in a new numbered step. Preserve failed observations and skipped checks. End the demo with one thing the agents got wrong and the evidence that helped the team catch it.
